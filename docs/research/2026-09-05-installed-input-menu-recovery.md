# 已安装洛克输入法的菜单身份错位：现场恢复记录

## 环境与初始失败

- 安装版本：0.2.26 / build 28。
- 正式安装目录：`/Library/Input Methods/洛克输入法.app`。
- `scripts/test-installed-input-menu.sh` 多次失败：TIS 当前源为 `im.roarkai.inputmethod.Luoke.Hans`，真实菜单勾选“豆包输入法”。
- 菜单自定义操作来自洛克。此现象不同于 9 月 3 日记录中菜单操作也来自豆包的情况。
- 安装包身份、名称、mode ID、图标正确；系统设置显示“洛克输入法”及 R 图标。
- TIS 枚举中豆包、洛克的 parent 和 mode 均启用，洛克 mode 被选中，但没有启用的系统键盘布局。查询当前及 ASCII-capable 布局仍可返回 `com.apple.keylayout.ABC`，因此仅查询当前布局不足以证明其已启用。

## 无效实验

以下操作没有修复真实菜单：

1. 从系统设置关闭再打开菜单栏输入法菜单。
2. 通过正式包的公开 TIS 注册/启用/选择路径重新选择洛克。
3. 显式调用 `TISEnableInputSource` 启用洛克 parent；返回 0。
4. 仅作为现场诊断，定向重启一次当前用户的 `TextInputMenuAgent`。重启后菜单不再勾选豆包，但洛克甚至不出现在菜单中；TIS 仍表示洛克被选中。

菜单代理日志出现 `KeyboardLayouts: no input source available` 和 `unknown input source id:com.apple.CharacterPaletteIM`。这些日志是线索，不单独作为根因证明。

未清理 LaunchServices 中的临时副本注册记录，未删除输入法或用户数据，未手写系统输入源偏好。本次诊断性代理重启不进入产品安装脚本。

## 有效恢复操作

通过 **系统设置 → 键盘 → 文本输入 → 编辑 → ＋ → 英语 → ABC → 添加**，添加系统键盘布局。

结果：

- 菜单立即出现 ABC、豆包输入法、洛克输入法。
- 洛克的选中名称与 TIS 一致，自定义命令区标题也为洛克。
- 连续三次运行 `scripts/test-installed-input-menu.sh` 通过。
- 随后进行了三轮真实菜单“豆包 → 洛克”切换：每次切换后等待一秒，豆包的 TIS ID 正确；返回洛克后菜单验收脚本全部通过。
- 最终选中洛克。

尝试从原生设置撤销刚添加的 ABC 时，其移除按钮为禁用状态。没有绕过该限制，因此最终保留 ABC，原有第三方输入法保留不动。

## 结论与边界

已验证的恢复办法是通过系统设置添加 ABC。现场证据指向系统输入源列表状态，而非洛克包内名称或图标错误；修复本次现场无需重新打包。

由于没有强行移除 ABC 重造原始异常，尚不能完全区分“缺少系统键盘布局”与“原生添加操作触发了输入源列表重建”的作用，也不能确定原始异常由哪一次历史操作造成。不能据此宣称所有 macOS 环境都必须使用 ABC，或把自动修改用户键盘布局写入安装器。

原生菜单切换不是同步操作：一轮未等待传播的检查曾在点击豆包后短暂读到洛克，随后读到豆包。跨进程验收须留出传播时间；这与初始持续错位不同。

本记录只验证菜单身份恢复与切换，不代表语音识别、系统翻译和跨应用输入的全部验收完成。
