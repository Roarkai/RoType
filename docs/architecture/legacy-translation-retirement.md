# 旧翻译链路清退与自定义方案兼容

状态：开发工作区已完成清退，尚未发布安装包。

## 唯一活动路径

Rime 选中候选 → F19 快照 → 原生候选会话 → v2 XPC / 静态兜底 → 独立译文栏 → F20 校验提交。

两个官方方案只引用 `rotype_candidate_session` 与 `rotype_candidate_filter`。后者只排序和保留原始候选，不读文件、不发布翻译请求属性、不生成译文。原文 echo 的既有位置保留；译文不占第 8/9 项，也不占任何其他候选编号。

已移除：

- 原生响应文件的写入、编码、读取校验与会话结束清理对象。
- Lua 响应文件读取、旧原文属性发布、动态译文插入及静态编号翻译词表。
- F18 composition 刷新与编号译文的特殊提交逻辑。
- 开发安装脚本创建 TranslationBridge 目录的行为。
- 验证旧文件链路的测试，改为验证候选排序、原文合约、无文件读取、整句/分段提交与兼容加载。

不移除通用 F18 键码映射，它属于正常键盘输入能力；也不移除 XPC v1 selector，后者是另一个升级兼容边界。

## 兼容入口

为了使只引用随包模块的旧自定义方案仍能加载，暂留四个很小的入口：

| 旧模块 | 当前行为 |
| --- | --- |
| rotype_dynamic_bilingual_filter | 转交纯候选排序模块 |
| rotype_bilingual_translator | 不输出候选 |
| rotype_dynamic_refresh | 返回 kNoop，不拦截 F18、不重组输入 |
| rotype_full_translation_commit | 返回 kNoop，不拦截数字或空格提交 |

这只是**加载与普通输入兼容**，不是继续支持旧编号译文。没有 `rotype_candidate_session` 的旧方案不会自动获得新译文栏；可切回官方方案，或由用户自行在 processors 中添加该模块（置于 recognizer 之后、key_binder 之前），并在 filters 的简化、去重之后使用 `rotype_candidate_filter`。

若用户目录中存在自行复制或修改的同名 Lua 文件，它仍可能覆盖随包模块。此轮不扫描、替换或删除这些私人副本，也不承诺任意第三方自定义逻辑的行为。历史 factory 数据迁移白名单保留原样，以维持已有备份行为。

`install-rime.sh` 是用户主动调用的开发安装工具：它会备份并覆盖已知 RoType 方案/模块，但保留 default.custom.yaml 和无关自定义模块。新增回归验证新模块完整复制、旧方案备份、用户配置不变。

## 验证与边界

- Lua 边界测试确认无响应文件读取、无旧属性发布、旧候选类型被过滤、排序保持，以及重音 echo 不会重复自身。
- 真实 Rime 使用新工厂数据、重新编译的方案运行；覆盖已确认前缀的整句翻译、当前分段替换、分页与原文快照。
- 隔离的旧自定义方案引用全部兼容入口，验证普通中文选择仍可提交、F18 不改输入、全分页没有编号 hello。
- 词条继续只在共享原生合约维护。旧测试与响应存储源码移到仓库外临时备份，未清除用户词库、配置、历史响应缓存或语音数据。
- 清退阶段没有同时改变性能模型；后续步骤 10 已完成基线对照与惰性处理，见 [性能记录](candidate-performance.md)。
- 实机跨应用与安装升级仍在最终验收阶段，不用本层测试替代。
